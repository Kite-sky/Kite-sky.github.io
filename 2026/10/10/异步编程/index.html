C#并发编程

写在前面

工作中经常用到异步编程，经常使用到Task和Task<T>对象，async和await关键字来实现C#中的异步编程。在使用中碰到有一些问题比如：为啥异步无返回值的方法有时添加await Task.CompletedTask；UI中的Click事件改造成异步方法；以及Task的各种用法；感念不清楚等问题。故整理了这篇文章。

一、概念简介

1.1 并发编程

**并发：**同时做多件事情

并发编程的实现形式：

  1. **多线程：**并发的一种实现形式，采用多个线程来执行程序。

  2. **异步编程：**并发的一种实现形式，它采用future模式（补充）或callback机制，以避免产生不必要的线程。

    一个future（或promie）类型表示一个即将完成的操作。在Net中，新future类型有Task和Task。老版本异步API中采用回调或事件，而不是future。

    异步编程核心理念是异步操作：启动了的操作将会在将来的某个时间点完成。这个操作执行时，不会阻塞原来的线程；启动这个操作的线程可以继续执行其他任务；当操作完成时会通知它的future或调用回调函数，以便让程序知道操作已经结束。

  3. **响应式编程：**并发的一种实现形式，一种声明式的编程模式，程序在该模式中对事件做出响应。

    异步编程意味着程序启动一个操作，而该操作将会在一段时间后完成· 响应式编程与异步编程非常类似，不过它是基于异步事件（asynchronous event）的，而不是异步操作（asnchronous operation）。 异步事件可以没有一个实际的“开始”，可以任何时间发生，并且可以发生多次，例如用户输人。

二、异步编程

2.1 异步编程的好处

对于GUI程序，异步编程提高了相应能力。一些耗时的操作（IO操作，数据库读写等）可以使用异步编程。

对于服务器端应用：异步编程实现可扩展性。一个服务器可能同时处理多个客户端的请求。这种通信等待网络或互联网上其他计算机的相应往往消耗大量时间。

2.2 异步编程的实现

现代的异步 .NET 程序使用两个关键字：async 和await。 async 关键字加在方法声明上，它的主要目的是使方法内的 关键字生效（为了保持向后兼容，同时引人了这两个关键字）。如果 async 方法有返回值，应返回Task；如果没有返回值，应返回 Task。 这些task 类型相当于 future，用来在异步方法结束时通知主程序。

⚠️不要用void作为async方法的返回类型！async方法可以返回void，但是这仅限于编写事件处理程序。一个普通的 async 方法如果没有返回值，要返回Task，而不是 void。

分析async/await特性结构

该特性有3部分组成：

  • 调用方法：该方法调用异步方法，然后在异步方法执行其任务的时候继续执行（可能在相同线程上，也可能在不同线程上）。

  • 异步方法：异步执行工作，然后立即返回到调用方法。

  • await表达式：用于异步方法内部，指明需异步执行的任务。

2.3 异步方法

特征

  • 有async 修饰符修饰

  • 方法体包含一个或多个await 表达式

  • 有以下返回类型

    • void：如果调用方法仅想调用异步方法，而不需要与它做任何交互时（称“调用并忘记”），异步方法可以返回void类型。如果异步方法中包含任何return 语句，则他们不能返回任何东西。
    • Task：如果调用方法不需要从异步方法中返回某个值，但需要检查异步方法的状态，那异步方法可以返回一个Task类型的对象。在这种情况下，如果异步方法中包含任何 return语句，则它们不能返回任何东西。
    • Task：如果调用方法要从调用中获取一个T类型的值，异步方法的返回类型就必须是Task。 调用方法将通过读取 Task 的 Resu1t属性来获取这个T类型的值。
    • ValueTask：这是一个值类型对象，它与 Task 类似，但用于任务结果可能已经可用的情况。因为它是一个值类型，所以它可以放在栈上，而无须像 Task 对象那样在堆上分配空间。因此，它在某些情况下可以提高性能。

2.4 异步方法控制流

异步方法包含三个不同的区域。第一个await前；await表达式；后续部分。

下图阐明了一个异步方法的控制流。它从第一个 await 表达式之前的代码开始，正常（同步地）执行直到遇见第一个 await。 这一区域实际上在第一个 await 表达式处结束，此时await的任务还没有完成（大多数情况下如此）。当 await 的任务完成时，方法将继续同步执行。如果还有其他 await，就重复上述过程。

2.5 异步编程中常用方法

1. Task.Delay(TimeSpan)

作用：异步等待一段时间，不占用线程（异步 Sleep）

  • 返回Task，可以await
  • 适合：请求超时控制、重试间隔
  • 特点：等待期间线程释放；支持传入CancellationToken提前取消延时

⚠️ 坑：不是 Thread.Sleep；Task.Delay不会卡死线程。

2. Task.FromResult(T result)

作用：快速创建已经完成的成功 Task，包装一个现成返回值

  • 没有任何异步操作，直接返回已完成任务
  • 使用场景：异步接口实现，不需要真正 IO，直接返回本地缓存结果，不用额外 await

⚠️ 坑：只造成功任务；对应还有Task.FromException（已失败任务）、Task.FromCanceled（已取消任务）。

3. IProgress （进度上报，不是 Task 静态方法，配套异步）

作用：异步任务向外报告执行进度，自动切回原始同步上下文（WPF 自动回到 UI 线程）

  • 适合：文件下载、批量报文处理，实时更新 UI 进度条

⚠️ 重点：Progress<T>在构造时捕获同步上下文；不要在 ConfigureAwait (false) 内部新建 Progress。

4. Task.WhenAll (Task [] tasks) ✅高频

作用：异步等待所有任务全部完成，全部跑完才继续

  • 返回Task<TResult[]>；成功时收集所有返回值；任意任务异常，整体抛出 AggregateException
  • 适用：批量 HTTP、多路 CAN 采集，全部任务都要执行完

⚠️坑：一个抛异常，await 立刻抛出；剩余任务还会继续后台执行，不会自动取消。

5. Task.WhenAny(Task[] tasks)

✅作用：异步等待任意一个任务最先完成（成功 / 异常 / 取消都算完成）

  • 返回最先完成的 Task；剩下任务继续后台跑，不会停止
  • 适用：冗余请求、超时控制（搭配 Task.Delay）

⚠️坑：只会拿到第一个完成任务，其他任务仍在后台运行，需要手动 CancellationToken 取消。

6. ConfigureAwait (bool)

不是创建 Task 方法，await 的链式调用配置

  • ConfigureAwait(true)【默认】：await 恢复后，切回原来的同步上下文（WPF 回到 UI 线程，可以直接操作 UI）
  • ConfigureAwait(false)：await 恢复后，不切回原上下文，使用线程池线程，减少死锁、性能更好

规则：IO 底层逻辑，后面代码不操作 UI → .ConfigureAwait(false)坑：如果后面要写 WPF 界面，不能 false，否则跨线程报错。

7. Task.Wait()

作用：同步阻塞，等待单个 Task 完成，卡住当前线程直到任务结束

  • 有重载支持超时；异常会包装成AggregateException
  • 风险：UI 线程调用极易死锁（你前面调试遇到的 Result 死锁同源）

替代：await task

8. Task.WaitAll(Task[] tasks)

作用：同步阻塞，等待所有任务完成，当前线程卡死

替代：await Task.WhenAll()

9. Task.WaitAny(Task[] tasks)

作用：同步阻塞，等待任意一个任务完成，当前线程卡死

替代：await Task.WhenAny()

2.9 取消异步编程

一些.NET 异步方法允许你请求终止执行。你也可以在自己的异步方法中加人这个特性。System.Threading.Tasks 命名空间中有两个类是为此目 的而设计的：CancellationToken 和CancellationTokenSource。

  • cancellationToken 对象包含一个任务是否应被取消的信息。
  • 拥有 cancellationToken 对象的任务需要定期检查其令牌（token）状态。如果 CancellationToken对象的 lscancellationRequested 属性为 true，任务需停止其操作并返回。
  • CancellationToken 是不可逆的，并且只能使用一次。也就是说，一旦IsCancellationRequested属性被设置为 true，就不能更改了。
  • cancellationTokenSource 对象创建可分配给不同任务的 cancellationToken 对象。任何持有 CancellationTokenSource 的对象都可以调用其 Cancel 方法，这会将 CancellationToken的 IsCanceIIationRequested 属性设置为 true。

三、并行开发

3.1 并行开发简介

现在电脑具有多个CPU核心，使多个线程同时执行。 若要利用硬件，可以将代码并行化，以跨多个处理器分配工作。

下图简要概述了 .NET 中的并行编程体系结构。

类 作用
Task 无返回值任务
Task<TResult> 带返回值任务
Parallel 高层并行 API：For/ForEach/Invoke
ParallelOptions 并行配置：最大并发、取消令牌、任务调度器
ParallelLoopState 并行循环内控制：Break() / Stop()
ParallelLoopResult 并行循环执行结果
CancellationTokenSource / CancellationToken 取消任务
AggregateException 并行 / 多任务聚合异常，包含多个内部异常
TaskScheduler 任务调度器，控制任务跑在哪类线程（线程池 / UI 线程）
TaskFactory 任务工厂，批量创建 Task

3.2 任务并行库（Task Parallel Library）

TPL 是 .NET 内置的任务并行库，命名空间：System.Threading.Tasks，从 .NET Framework 4.0 引入，是现代 C# 异步、并行编程的核心。

TPL 核心：Task、Task<TResult>、Parallel、TaskScheduler，自动管理线程池，不用手动操作 Thread。

⚠️ 重点区分：

  • 并行 Parallel：多核 CPU 同时执行，适合 CPU 密集型；不是异步！会阻塞调用线程。
  • 异步 async/await：IO 密集型，不阻塞线程。

两大分支：

  • 数据并行（Parallel）：同一操作对多个数据并行执行（CPU 密集循环）

  • 任务并行（Task）：多个独立任务并发执行，支持异步等待（最常用）

3.3 数据并行库

数据并行：是指对源集合或数组中的元素同时执行相同作（即并行执行）的方案。

API 作用
Parallel.For 并行 for 循环（数字索引）
Parallel.ForEach 并行遍历集合（IEnumerable）
Parallel.Invoke 并行执行一组独立 Action
ParallelLoopState 循环状态：提前停止、跳出循环
ParallelOptions 配置：最大并发数、取消令牌、任务调度器
ParallelLoopResult 返回循环执行结果：是否完成、是否被中断

3.3.1 Parallel.For 并行数字循环

签名：ParallelLoopResult Parallel.For(int fromInclusive, int toExclusive, Action<int> body)

带 ParallelLoopState：Break / Stop

  • Break()：尽快停止后续索引，已经启动的循环继续跑完（优先，类似 for break）
  • Stop()：立刻尽可能停止所有循环，不管索引

带本地状态重载（高性能，减少锁竞争）

适合累加计算，每个线程有独立本地变量，最后合并结果

3.3.2 Parallel.ForEach 并行便利集合

最常用，遍历数组、List、IEnumerable。

带分区器 + ParallelLoopState

带本地状态重载（同 For，适合并行聚合）

3.3.3 Parallel.Invoke 并行执行多个方法

一次性并行执行多个无返回 Action。

特点：

  1. 所有 Action 尽可能并行；阻塞主线程直到全部完成
  2. 任意 Action 抛异常，会聚合到AggregateException

3.3.4 ParallelOptions 配置项

MaxDegreeOfParallelism

  • 默认：-1，由线程池自动调度
  • 场景：访问有限资源（数据库连接、硬件端口），限制并发，防止打爆资源

3.3.5 ParallelLoopResult 返回值

  • IsCompleted：true = 循环全部跑完，没有 Break/Stop
  • LowestBreakIteration：调用 Break 的最小索引；Stop 时为 null

3.3.7 AggregateException 异常处理

并行中多个任务可以同时抛出异常，会打包进 AggregateException

3.3.8 Parallel的使用场景分析

适用场景

  1. CPU 密集计算：图像处理、批量数据运算、文件解析（计算量大）
  2. 大量独立任务，任务之间无强依赖
  3. 需要简单并行，不想手动管理 Task/Thread

❌ 不适合场景

  1. IO 密集：网络请求、数据库查询（线程会阻塞浪费资源，优先Task.WhenAll）
  2. 任务极短：循环体逻辑很小，并行开销 > 收益（并行有线程调度成本）
  3. 共享变量不加锁：多个线程同时写同一个变量，会出现竞态条件

推荐：优先使用本地状态重载，减少锁；必要用 Interlocked / lock

3.3.9 Parallel和Task.All对比

Parallel Task.WhenAll
阻塞 阻塞调用线程 不阻塞（await）
适用 CPU 密集 IO 密集
返回 void / ParallelLoopResult Task
控制 MaxDegreeOfParallelism 手动控制并发
